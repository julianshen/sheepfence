# SheepFence SDK API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after user approval. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the reviewed geofence engine into an integration-ready Swift SDK with an explicit, documented public contract.

**Architecture:** One public `SheepFenceClient` facade over the existing actor engine, transactional store, importer and foreground location provider. Separate side-effect-free queries from monitoring inputs. Keep geometry, persistence, transport and sampling implementation types internal.

**Tech Stack:** Swift 6, Swift Package Manager, Core Location, Core Data, Swift Testing, DocC; proposed iOS 16+ support.

## Recommended integration

```swift
import SheepFence

// Main actor; restores committed datasets before returning.
let client = try await SheepFenceClient.open(
    storeURL: storeURL,
    configuration: .init(maximumLocationAge: 60)
)

// Install a bundle file, local file, or HTTPS URL. Same revision rules as today.
let install = try await client.installSnapshot(from: bundledGeoJSONURL)

// Subscribe before starting. Registration is complete when events() returns.
let stream = try await client.events()
let eventTask = Task { @MainActor in
    do {
        for try await event in stream {
            // Render state snapshots; handle enter/exit and dataset changes.
            handle(event)
        }
    } catch {
        // Includes explicit slow-consumer termination; resubscribe for fresh state.
        showMonitoringError(error)
    }
}

// The host requests location permission, then starts only while foreground active.
try await client.startMonitoring(mode: .sdkManaged)

// On leaving foreground; cancel event consumption when its owner is disposed.
await client.stopMonitoring()
eventTask.cancel()
```

A new store's parent directory is created by `open`. Failed/corrupt existing stores throw; the SDK never silently deletes them. Exactly one live client per canonical store URL is allowed within a process; duplicate opens throw `storeAlreadyOpen`. Sharing a store across processes/app extensions is unsupported. Configuration is immutable for a client. The example's 60 seconds is illustrative, not a product recommendation.

## Proposed public facade

```swift
@MainActor
public final class SheepFenceClient: GeofenceClient {
    public static func open(
        storeURL: URL,
        configuration: GeofenceConfiguration
    ) async throws -> SheepFenceClient

    public func installSnapshot(from source: URL) async throws -> InstallResult
    public func installSnapshot(data: Data) async throws -> InstallResult
    public func datasets() async -> [DatasetSummary]
    public func regions(in datasetID: String? = nil) async throws -> [RegionSummary]
    public func removeDataset(id: String) async throws -> DatasetRemovalResult

    public func query(coordinate: Coordinate, in region: RegionID) async throws -> GeometryQueryResult
    public func contains(coordinate: Coordinate, in region: RegionID) async throws -> Bool
    public func distance(from coordinate: Coordinate, to region: RegionID) async throws -> RegionDistanceResult
    public func evaluate(location: LocationSample) async throws -> EvaluationBatch

    public func startMonitoring(mode: LocationSourceMode) async throws
    public func submit(location: LocationSample) async throws -> EvaluationBatch
    public func updateAvailability(_ availability: LocationAvailability) async throws
    public func stopMonitoring() async

    public func state() async -> MonitoringState
    public func events(bufferCapacity: Int = 256) async throws -> AsyncThrowingStream<GeofenceEvent, Error>
}
```

All protocol operations match the facade's declarations; convenience operations may live in protocol extensions. Keep `GeofenceClient` public for app mocks; expose public initializers for all immutable result/event payload values. Async calls return values across actors; heavy parsing, disk and geometry work never execute on the main actor. Foundation value types are `Sendable`; do not expose Core Data or Core Location managers.

Add `LocationSample.init(_ location: CLLocation)` and equivalent `evaluate(location: CLLocation)` / `submit(location: CLLocation)` conveniences. Invalid Core Location speed maps to nil. Validation happens at API boundaries, not by trapping constructors.

## Distance to a region

Added at user request. This is a coordinate-only, side-effect-free query, usable while
stopped or in either monitoring mode. It does not acquire GPS or emit events.

```swift
let result = try await client.distance(
    from: Coordinate(longitude: location.coordinate.longitude,
                     latitude: location.coordinate.latitude),
    to: regionID
)

switch result.boundaryDistance {
case .approximateMeters(let meters):
    // Distance to the nearest region edge, including hole boundaries.
    print(meters)
case .unsupported(let reason):
    // No reliable local-model distance is available for this query.
    print(reason)
}
```

```swift
public enum BoundaryDistanceEstimate: Equatable, Sendable {
    case approximateMeters(Double)
    case unsupported(DistanceUnsupportedReason)
}

public enum DistanceUnsupportedReason: Equatable, Sendable {
    case outsideLocalModelRange
    case numericalFailure
}

public struct RegionDistanceResult: Equatable, Sendable {
    public let regionID: RegionID
    public let revision: Int
    public let membership: Membership
    public let boundaryDistance: BoundaryDistanceEstimate

    public var distanceToBoundaryMeters: Double? { get }
    public var distanceToRegionMeters: Double? { get }
    // Public initializer for app mocks; validate finite nonnegative estimates.
    public init(regionID: RegionID, revision: Int, membership: Membership,
                boundaryDistance: BoundaryDistanceEstimate) throws
}
```

| Value | Meaning |
|---|---|
| `membership` | Coordinate containment, using the existing boundary and hole rules; independent of meter-model support. |
| `distanceToBoundaryMeters` | Nearest edge distance from inside or outside; nil for unsupported distance. |
| `distanceToRegionMeters` | Zero when inside; nearest edge distance when outside; nil when outside and distance is unsupported. |
| `revision` | The exact committed dataset revision used for both membership and distance. |

Distances are unsigned approximate straight-line meters, not routing distance, travel
time or GPS-confidence bounds. The input coordinate is used as given: accuracy,
freshness and boundary buffer are not applied. On a boundary the supported distance
is zero regardless of whether containment classifies that boundary as inside or
outside. A point in a hole is outside and its distance to the region is the nearest
hole edge. For a supported MultiPolygon, take the minimum over all shell/hole edges
in all components. Named disabled regions are queryable, just as with `query`.

Use the existing local-model envelope: absolute query latitude at most 80 degrees,
and every geometry vertex within one degree of query latitude and one degree of
unwrapped longitude. A distant component makes the whole distance unsupported even
if another component is nearby; do not claim a global distance from partial geometry.
Invalid coordinates throw `invalidCoordinate`; missing dataset/region follows `query`.
Unsupported model range is a result, not an exception. Numerical nonfinite results
must likewise be explicit, never infinity, NaN or a fabricated zero.

**Implementation constraint:** the current internal distance helper returns zero as
a conservative uncertainty fallback outside its support envelope. Do not expose that
fallback as a measured distance. Refactor to return an explicit estimate and preserve
the conservative fallback only in internal observation/sampling adapters. A genuine
supported zero must remain distinguishable from unsupported distance.

## Configuration

Retain `GeofenceConfiguration`, with explicit required `maximumLocationAge` and existing `boundaryBufferMeters`, `maximumFutureSkew`, `expectedDatasetIDs`. Add:

- `downloadPolicy: DownloadPolicy = .standard`: proposed defaults 5,000,000 bytes, 30-second transport timeout. These are resource limits, not geofence tuning. Validate local files and Data against the same byte cap. Accept HTTPS only remotely; reject redirects. Apps with authenticated transport download their own Data and call `installSnapshot(data:)`; SDK does not manage their credentials.
- `sampling: SamplingMode = .fixed(.standard)`: `.fixed(LocationSamplingConfiguration)` or `.adaptive(SamplingPolicyConfiguration)`. Proposed fixed standard: 10 m desired accuracy and 10 m distance filter. These are Core Location requests, not guaranteed accuracy/update frequency. Adaptive tuning stays opt-in until field validation; retain documented explicit adaptive parameters.

Keep current four-argument `open` as a deprecated forwarding overload for one pre-1.0 migration cycle. Do not silently preserve the old stateful meaning of `evaluate`; announce that behavior change in migration documentation.

## Queries versus monitoring

| Operation | Changes monitoring state / emits events? | Contract |
|---|---|---|
| `query` / `contains` | No | Exact coordinate-only membership for one region, including disabled regions when explicitly named; no accuracy inference. `query` attributes the committed revision. |
| `distance` | No | Coordinate-only membership and approximate nearest-edge distance with explicit unsupported results, attributed to one revision. |
| `evaluate` | No | One-shot uncertainty-aware result for every enabled region; allowed while stopped or in either monitoring mode. No timestamp ordering relative to monitoring, no last-confirmed history. Invalid/stale/future samples return unavailable observations. |
| `submit` | Yes | Host-provided monitoring input; requires active `.hostProvided`. Applies freshness, ordering, uncertainty and transition rules. |
| SDK provider callback | Yes | Same stateful path as `submit`, used only in `.sdkManaged`. |
| `updateAvailability` | Yes | Requires active `.hostProvided`; a host cannot override SDK-managed provider status. |

`EvaluationBatch` contains `evaluatedAt`, input `sampleTimestamp`, `[DatasetMetadata]` used, and deterministic `[RegionEvaluation]` results. Sort results by priority descending, then dataset ID and feature ID ascending. One-shot evaluations always have `lastConfirmed == nil`; stateful results retain it. One-shot evaluation validates only the supplied sample and dataset readiness; it ignores provider authorization/availability, so a host-owned sample still works when SDK location permission is denied. All data comes from one committed in-memory snapshot view. An installed empty dataset returns an empty batch; missing required data throws `datasetNotReady`.

Repeated start with the same mode and repeated stop are idempotent. Switching mode requires stop first. Start with no enabled regions is allowed and keeps the provider stopped; installing enabled regions activates it. Restart creates a fresh baseline, never a synthetic entry. Stop waits for provider shutdown and rejects old-generation callbacks; it clears current observations and emits stopped state, while datasets and subscriptions survive. Stop is cleanup and completes even if its caller is cancelled. The host remains responsible for foreground lifecycle.

## GPS unavailable and recovery contract

GPS loss never means outside a region. It never alone produces an exit event.

| Situation | Current state and events | Recovery |
|---|---|---|
| Permission not determined, denied, restricted, services disabled, provider no-location | Explicit `LocationUnavailableReason`; availability event then state snapshot with all enabled regions unavailable, historical `lastConfirmed` retained. | First confirmable observation establishes a baseline, with no inferred crossing across the outage. |
| No callback and last sample expires | `state()` and subscription snapshots project `.unavailable(.staleLocation)`; no timer-generated event is promised. UI must use timestamps or refresh state to avoid presenting stale data as current. | Reset baseline before the next accepted sample, even if state() was never called. |
| Invalid/future/out-of-order input | Return/publish unavailable evaluations for that input; do not advance accepted timestamp or overwrite last valid sample. | Input rejection alone does not reset transition history; actual freshness gap or availability loss does. |
| Reduced-accuracy location | Report reducedAccuracy separately; evaluate normally with horizontalAccuracy. It can yield confirmed or uncertain observations. | Do not interpret reduced accuracy alone as no GPS. |
| No GPS but caller has a coordinate | `query`, `contains` and `distance` still work offline; pure `evaluate` uses caller-supplied sample validity independently of provider availability. | No monitoring state or events are changed. |

`MonitoringState.evaluations` tracks the latest attempted monitoring evaluation, while
freshness is determined from the last accepted sample; neither substitutes a bad sample
for lastConfirmed. When stopped, mode is nil, availability is monitoringStopped and
current evaluations are empty. Before the first usable sample, active monitoring
reports noLocation unless a more specific provider reason is known. If datasets are
not ready, report readiness separately and do not invent per-region observations.
For a stateful input that throws before a batch can be formed, no `.evaluated` batch
is emitted: host submit throws, SDK-managed ingestion emits `.evaluationFailed`.

## Discovery, deletion and readiness

- `DatasetSummary`: `metadata`, `regionCount`, `enabledRegionCount`. `datasets()` returns an empty list for a new store, sorted by ID.
- `RegionSummary`: `id`, `revision`, `name`, `enabled`, `priority`. Includes disabled regions for catalog display; all-dataset listing can be empty. A specifically requested missing dataset throws.
- `DatasetRemovalResult`: `datasetID`, `removedRegionIDs`, `wasPresent`. Removing a missing ID is an idempotent no-op. Removal commits to disk before memory changes, discards region history and emits `.datasetRemoved`, never exited events. It updates readiness and provider activity. A failed deletion preserves old data.
- `MonitoringState`: `mode: LocationSourceMode?`, `readiness: DatasetReadiness`, `availability: LocationAvailability`, `datasets: [DatasetSummary]`, `evaluations: [RegionEvaluation]`. `DatasetReadiness` becomes public with `.noDatasets`, `.missingRequired(Set<String>)`, `.ready`; zero enabled regions can still be ready.
- `state()` is an atomic snapshot. It describes the latest observation, including timestamps; it is not a claim that an old sample is still fresh. At read/subscription time, expired observations are projected as unavailable with last confirmation retained. This does not generate crossing events. Late subscribers can build their UI without manufacturing events. Before accepting a new monitoring sample, a gap since the last accepted sample exceeding maximumLocationAge resets transition baselines, independent of calls to state(). Explicit availability loss also resets transition baselines. The first confirmable recovery sample emits baseline, not entered/exited; lastConfirmed remains historical context until replaced. Rejected out-of-order/future/invalid-accuracy samples do not advance the accepted timestamp or alone erase the baseline.
- Region names/enabled/priority are controlled by replacement snapshots; no second mutable override layer in v1. Removal and installs serialize per dataset; a pending install that commits after a removal may recreate the dataset. Removal is not cancellation of a pending install.

## Events and backpressure

Retain `.baseline`, `.entered`, `.exited`, `.datasetChanged`, `.locationAvailabilityChanged`, `.evaluationFailed`. Add `.stateSnapshot(MonitoringState)`, `.evaluated(EvaluationBatch)` and `.datasetRemoved(DatasetRemovalResult)`.

Every stateful input that produces an EvaluationBatch publishes `.evaluated` after any baseline/enter/exit events from that input, including unchanged, boundary-uncertain and rejected samples. Availability changes also publish a state snapshot after the availability event so consumers can refresh every affected region. Pure evaluate emits nothing. This lets SDK-managed consumers render current uncertainty without polling. No freshness timer is promised: consumers use sample timestamps or call state() when rendering/resuming to project expiration.

Each subscription registers atomically with an initial `.stateSnapshot` before later events. Streams are independent and ordered, with no historical transition replay. Starting/stopping emits a state snapshot when mode changes. Installing a changed snapshot emits datasetChanged with affected evaluations, not movement events. Removing data emits datasetRemoved; consumers can call state() to refresh readiness.

Replace the current unbounded queue with a positive configurable capacity (default 256). If full, terminate that subscriber with `GeofenceError.eventBufferOverflow`; do not silently drop enter/exit events or block location processing. Buffered events may drain before the error is delivered. Re-subscribing yields current state, but cannot recover missed historical transitions. This is an in-process observation API, not a durable event log. Cancellation removes the subscriber; releasing the client finishes its streams.

## Errors, cancellation and storage guarantees

Keep structured import diagnostics (`feature ID`, JSON path, reason), revision conflict, readiness and source-mode errors. Add structured source failures (HTTP status, timeout, byte limit, rejected redirect, network failure), `storeAlreadyOpen`, `eventBufferOverflow`, and invalid buffer configuration. Keep localized prose for display/debugging only; callers switch on stable cases. Do not return raw credential-bearing URLs or server response bodies in diagnostic descriptions.

Use ordinary Swift `throws` in v1: errors are documented `GeofenceError` or `CancellationError`; normalize unexpected dependency errors at the SDK boundary. Import cancellation before the commit point preserves prior data. Once durable commit starts, finish the atomic operation and report its outcome even if cancellation arrives; never return a cancellation that implies rollback after a successful commit. No implicit retry. Repeated byte-identical installs remain unchanged; older revisions are skipped; equal revision/different bytes fail.

`open` restores committed snapshots before returning. No samples or movement history persist. Losing the client stops any owned provider and closes streams; verify this lifetime behavior rather than relying on UI owners to leak nothing.
